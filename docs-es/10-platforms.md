# Plataformas

> Estado: borrador (draft).

**En un párrafo.** El runtime que controla el escritorio es multiplataforma, pero no de forma uniforme. pi, gentle-ai y engram documentan Windows, macOS y Linux. El README de gentle-shell no declara soporte para ningún sistema operativo; su soporte se infiere de su aprovisionamiento durante la instalación (rutas para Darwin, Linux y Windows) y de su CI en los tres. En Windows, cada uno tiene sus propias condiciones: pi necesita Bash (Git Bash por defecto), gentle-shell compila su gentle-ai privado desde el código fuente con una cadena de herramientas local de Go 1.25.10+, gentle-ai no publica binarios para Windows hasta que exista la firma Authenticode, y engram publica binarios para Windows sin firmar que algunos antivirus marcan. El propio escritorio solo se ha probado en macOS Apple silicon, no tiene CI y hoy no puede iniciar un chat en Windows debido al lanzamiento del shim por lotes (audit A4). Ejecutar el runtime dentro de WSL está documentado por pi, pero ninguna fuente fijada recomienda WSL frente a Windows nativo, y ningún proyecto prueba WSL en la CI. Esta página expone las evidencias, lo que el escritorio debe resolver en cada plataforma y topología, y los riesgos.

**Qué dice la matriz.**
- **macOS y Linux** tienen artefactos de release o una instalación documentada para las cuatro piezas upstream. La CI es desigual: hay CI en Linux para las cuatro; hay CI en macOS para gentle-shell y gentle-ai, para pi solo como prueba smoke de binarios en el momento de la release (`pi@a13d35a:.github/workflows/build-binaries.yml:3-7`, `:139`), y ninguna para engram (sus flujos de trabajo solo usan `ubuntu-latest` y `windows-latest`). El escritorio es el eslabón débil: no se ha probado en Linux ni en macOS Intel.
- **Windows nativo** está documentado por pi, gentle-ai y engram, y gentle-shell lo aprovisiona y lo prueba en la CI (soporte inferido, no declarado en su README), con condiciones que el usuario debe cumplir (Bash para pi, Go para el gentle-ai de gentle-shell, fricción con los antivirus para engram).
- **WSL** está documentado por pi y reconocido por el `doctor` de gentle-ai y por sus errores de modo de archivo. Ningún proyecto ejecuta WSL en la CI.
- **[community]** La nota de Matrak dice que Windows está soportado "native, or via WSL — recommended" ([issue #28, "Author's framing: review of the vision (2026-10-03)"](https://github.com/Gentleman-Programming/gentle-shell-desktop/issues/28), punto 5). `UNVERIFIED:` ninguna fuente fijada recomienda WSL frente a nativo; lo más cercano es la tabla de prioridades del PRD en borrador de gentle-ai (`gentle-ai@ff77164:PRD.md:78-79`), un documento de planificación con fecha 2026-02-27, cuya pregunta abierta 3 plantea cuánto invertir en Windows nativo (`PRD.md:1363`).

## Qué debe resolver el escritorio

### Descubrimiento del lanzador

- **Hoy.** `GENTLE_SHELL_BIN`; si no, `gentle-shell` en `PATH`; en win32 los candidatos son `gentle-shell.cmd`, `gentle-shell.exe`, `gentle-shell`, en ese orden (`gentle-shell-desktop@5ab4a00:src/main/adapters/launcherLocator.ts:19-23`, `:44-57`).
- **La ruta `.mjs`.** Un `GENTLE_SHELL_BIN` que termina en `.mjs` se ejecuta con el binario de Electron y `ELECTRON_RUN_AS_NODE=1` (`launcherLocator.ts:34-41`). El issue #23 verificó que es una solución provisional que funciona en Windows.
- **Opción.** `Inference:` resolver el shim de npm a `<npm prefix>/node_modules/gentle-pi/bin/gentle-shell.mjs` evita `cmd.exe` por completo. `UNVERIFIED:` la estructura del shim es cosa de npm y no está documentada en ninguna fuente fijada.

### Lanzamiento de shims por lotes

- **Causa raíz (audit A4).** El componente que lanza los procesos llama a `spawn` sin `shell` (`gentle-shell-desktop@5ab4a00:src/main/adapters/nodeProcessSpawner.ts:10`). Las versiones actuales de Node rechazan un archivo por lotes sin `shell: true` (`gentle-shell@ac67159:lib/gentle-shell-launcher.ts:969-974`).
- **La propia corrección de gentle-shell.** `planSpawn` une `[command, ...args]` mediante `quoteForCmdExe` y pasa `args: []` con `shell: true` (`gentle-shell@ac67159:lib/gentle-shell-launcher.ts:982-985`, `:1013-1019`). El lanzador la usa para el lanzamiento real de pi (`bin/gentle-shell.mjs:1393-1396`).
- **PR abierta #26** (abierta, sin fusionar a fecha de 2026-10-03; head `615dd87`). Establece siempre `windowsHide: true`, y `shell: true` en win32 cuando el comando (sin las comillas exteriores) termina en `.cmd`/`.bat`. Pasa el comando y los argumentos tal cual, sin entrecomillar.
- **Carencia.** El escritorio pasa rutas como argumentos: `--session <path>` cuando hay una ruta de sesión definida, y `--home <dir>` solo cuando `GENTLE_SHELL_HOME` está definido (en otro caso, `--link` o `--isolated`) (`gentle-shell-desktop@5ab4a00:src/main/domain/session/PiSession.ts:127-133`; `src/main/domain/home/home.ts:33-36`). El propio comando es una ruta tal cual: el localizador devuelve `path.join(dir, name)` sin entrecomillar (`src/main/adapters/launcherLocator.ts:53-54`), y la PR #26 se lo pasa a `spawn` sin cambios. La prueba de ruta entrecomillada de la PR #26 usa una cadena ya entrecomillada (`'"C:\\Program Files\\gentle-shell.cmd"'`) y solo comprueba `shell: true`. `Inference:` (no ejecutado) con `shell: true` y tokens sin entrecomillar, `cmd.exe` divide o reinterpreta un prefijo de npm o una ruta de argumento con espacios o `&|<>^%()`. La prueba RED de QW-01 pide "quoted tokens" ([QW-01](09-roadmap.md#qw-01-lanzamiento-de-cmd-en-windows-audit-a4)); la PR #26 no la cumple.

### Ventanas de consola

- **Issue #24.** Una consola visible por cada chat abierto; cerrarla mata el backend de ese chat. Quien lo informa señala que la ventana "may belong to the grandchild `pi` process".
- **Evidencias en ambas capas.** La PR #26 solo oculta el hijo directo. gentle-shell oculta sus sondeos internos de Git y del sistema (`windowsHide: true`, p. ej. `gentle-shell@ac67159:lib/session-worktree-registry.ts:34`), pero su lanzamiento de pi no pasa `windowsHide` (`bin/gentle-shell.mjs:1396`).
- `UNVERIFIED:` qué proceso es el propietario de la ventana. El propio protocolo de captura de gentle-shell muestra cómo demostrarlo (`gentle-shell@ac67159:docs/windows-startup-console-visibility.md:7-14`). La corrección puede necesitar a gentle-shell, no solo al escritorio.

### PATH y entorno en un arranque desde la GUI

- **macOS.** Las aplicaciones abiertas desde Finder no tienen el `PATH` de la shell, así que no se encuentran `gentle-shell` ni `node` (`gentle-shell-desktop@5ab4a00:README.md:52-58`; audit A18).
- **Windows.** gentle-ai ya sortea los procesos con un `PATH` desactualizado en Windows ("Fresh install detection falls back to known Engram/GGA install locations", `gentle-ai@ff77164:docs/platforms.md:65`), y avisa cuando `go install` escribe fuera del `PATH` resuelto (`docs/platforms.md:55`). `UNVERIFIED:` si un escritorio iniciado desde el menú Inicio ve un `PATH` modificado por un `npm i -g` reciente.
- **Linux.** `UNVERIFIED:` no se comprobó el entorno de un `AppImage` iniciado desde un acceso directo del entorno de escritorio.

### Directorios home

- **Homes del escritorio.** El home aislado es `<homedir>/.gentle-shell/agent`; el vinculado es `PI_CODING_AGENT_DIR` o `<homedir>/.pi/agent` (`gentle-shell-desktop@5ab4a00:src/main/domain/home/home.ts:45-47`, `:56-67`). En Windows nativo, `homedir` es el perfil de Windows; gentle-ai sitúa la configuración de Pi en Windows en `%USERPROFILE%\.pi\` (`gentle-ai@ff77164:docs/platforms.md:85`).
- **Lista de sesiones en el mismo proceso.** El escritorio lee las sesiones en el mismo proceso desde ese directorio (audit A1). `Inference:` cuando el runtime vive en WSL (topología B), sus homes están bajo el `/home` de Linux, así que la lista del lado de Windows leería el directorio equivocado salvo que los lea a través de `\\wsl$` (Microsoft: los archivos de Linux aparecen bajo `\\wsl$`, [filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)). `UNVERIFIED:` el almacén de sesiones de pi sobre una ruta UNC `\\wsl$`.
- **gentle-ai.** En v4.0.0, las formas absoluta o relativa de `PI_CODING_AGENT_DIR` solo se respetan cuando el home es el home real del usuario (`gentle-ai@ff77164:internal/agents/pi/adapter.go:384-393`). `UNVERIFIED:` el efecto sobre los homes gestionados por el escritorio.

### Modos de archivo (metadatos POSIX)

- **La limitación.** gentle-ai informa de que la ruta del modo de revisión local del clon "cannot be made private" cuando "the filesystem hosting it does not persist POSIX permission modes (WSL DrvFS without the metadata option, exFAT, and SMB without POSIX extensions…)" (`gentle-ai@ff77164:internal/cli/review_mode.go:290-297`; texto de reparación en `internal/reviewtransaction/rar_path_safety.go:70`). gentle-shell lo muestra como `candidate-owner-parent-chmod-ineffective` (`gentle-shell@ac67159:docs/readme-reference.md:528`).
- **Valor por defecto.** Microsoft documenta que la opción `metadata` de DrvFS está `disabled` por defecto ([wsl-config, automount options](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)).
- **Impacto en el escritorio.** `Inference:` un usuario de WSL cuyo repositorio está bajo `/mnt/c` no puede iniciar una revisión de RDD hasta que vuelva a montar con `metadata` o mueva el repositorio. La barra de estado de la maqueta muestra `ODD · RDD on` (`gs-mockup.html:822`), así que el escritorio debería mostrar este error con claridad, no como un fallo genérico. Microsoft también recomienda mantener los archivos del proyecto en el sistema de archivos de Linux cuando se trabaja desde una línea de comandos de Linux ([filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)).

### Empaquetado y firma

- **Hoy.** Sin firmar en todas las plataformas: en mac, `identity: null`; no hay ajustes de firma para `win` ni para `linux` (`gentle-shell-desktop@5ab4a00:electron-builder.yml:25-38`). Sin actualización automática (`README.md:64`).
- **Precedente upstream.** gentle-ai retiene todos los binarios de Windows hasta que exista la firma Authenticode (`gentle-ai@ff77164:docs/platforms.md:21`, `:59`). engram publica binarios de Windows sin firmar y documenta los falsos positivos de los antivirus (`engram@3951380:docs/INSTALLATION.md:109-127`).
- **Hoja de ruta.** La firma corresponde al [milestone M5](09-roadmap.md#m5-firma-y-actualización-automática); qué plataformas cubre M5 figura allí como `UNVERIFIED`. La parte de firma de audit A18 figura en M5.

### Topologías de WSL

| | A. Escritorio y runtime nativos en Windows | B. Escritorio nativo, runtime dentro de WSL | C. Escritorio y runtime dentro de WSL (WSLg) |
|---|---|---|---|
| **Qué se ejecuta y dónde** | `.exe` de Electron; `gentle-shell.cmd`, `pi.cmd`, `gentle-ai.exe` privado y `engram.exe` en Windows. | `.exe` de Electron en Windows; `gentle-shell`, pi, gentle-ai y engram en una distribución de WSL. | `AppImage` de Linux, mostrado mediante WSLg; todo el runtime en la distribución. |
| **Lanzamiento** | `cmd.exe` con tokens entrecomillados, como `planSpawn` (audit A4). | `wsl.exe` con el comando de Linux; "the commands passed into `wsl.exe` are forwarded to the WSL process without modification", y la distribución se elige con `wsl --distribution <name>` ([filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems); [basic commands](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)). | Igual que en Linux. |
| **Rutas** | Rutas de Windows. | "File paths must be specified in the WSL format" ([filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)), así que `--session` y `--home` necesitan traducción. Para las variables de entorno, el indicador `/p` de `WSLENV` "translates the path between WSL/Linux style paths and Win32 paths" (misma página). `Inference:` eso cubre las rutas transportadas en variables de entorno, no los argumentos de la línea de comandos, así que el escritorio debe traducir por sí mismo las rutas de los argumentos o pasarlas mediante variables traducidas. `UNVERIFIED:` `wslpath` y los indicadores `--cd`/`--exec` no están documentados en las páginas leídas. | Rutas de Linux. |
| **Entorno** | Heredado. | `Inference:` el `GENTLE_SHELL_INTERACTIVE_HOST` del escritorio (`PiSession.ts:134`) solo cruza si figura en `WSLENV`, "a list of environment variables to share between Windows and WSL" ([filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)). | Heredado. |
| **stdio** | Tuberías. | Microsoft documenta las tuberías y la redirección a través de `wsl` ([filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)). `UNVERIFIED:` JSONL de larga duración sobre esa tubería, y si matar `wsl.exe` detiene el árbol de procesos de Linux. | Tuberías. |
| **Homes y sesiones** | Perfil de Windows. | Homes de Linux; la lista de sesiones en el mismo proceso necesita acceso a `\\wsl$` (ver [Directorios home](#directorios-home)). | Homes de Linux. |
| **Requisitos** | Node, Git for Windows, Go ≥ 1.25.10 (ver [Cómo se instala cada pieza](#cómo-se-instala-y-se-ejecuta-cada-pieza)). | WSL 2. `Inference:` una distribución con Node ≥ 22.19 y el runtime instalado (se aplica la vía de instalación de Linux), y el escritorio debe saber a qué distribución dirigirse, ya que `wsl.exe` selecciona una con `--distribution <name>` ([basic commands](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)). | Windows 10 compilación 19044+ o Windows 11, WSL 2 y un controlador vGPU ([GUI apps](https://learn.microsoft.com/en-us/windows/wsl/tutorials/gui-apps)). |
| **Bloqueos conocidos** | audit A4, issue #24, `.exe` sin firmar. | Modos de archivo de DrvFS para repositorios bajo `/mnt/c`; descubrimiento del lanzador dentro de la distribución; ningún precedente probado en ningún repositorio fijado. | Compilación de Linux del escritorio sin probar (`README.md:7`). Microsoft: WSLg "does not provide a full desktop experience" ([GUI apps](https://learn.microsoft.com/en-us/windows/wsl/tutorials/gui-apps)). `UNVERIFIED:` notificaciones, bandeja del sistema y diálogos de archivos bajo WSLg. |
| **Valoración** | `Inference:` el camino más corto: todas las piezas upstream lo soportan y gentle-shell ya resolvió el lanzamiento. | `Inference:` el que más trabajo requiere: un mecanismo de lanzamiento nuevo y puentes para rutas, entorno y homes. Encaja con usuarios cuyo código vive en WSL (la propia orientación de pi, `pi@a13d35a:docs/windows.md:13`). | `Inference:` no necesita código nuevo, pero la experiencia es la de una aplicación de Linux en Windows. |
